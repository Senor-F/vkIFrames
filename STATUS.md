# vkIFrames: Implementation Status and Measurements

Last updated 2026-10-31. Complements [ROADMAP.md](ROADMAP.md) and [DESIGN.md](DESIGN.md). Source of truth is the git repository; this page records what was measured on hardware.

## Where the stages stand

| Stage | State |
| :--- | :--- |
| 1 Layer skeleton | Done. |
| 2 Present timing | Done. The Deck and the Wayland desktop expose `VK_EXT_present_timing`; the desktop reports feedback only (no absolute target times), so pacing stays vblank driven. Games that use present timing themselves are detected and the layer's own use is skipped. |
| 3 Hold one, ring buffer, blend | Done. 45 to 90 in Cuphead on the Deck is locked: shown 90.0 fps, 0 drops, base jitter 0.01 to 0.02 ms in steady state. |
| 4 Optical flow | Running on RADV (RX 9070) and on the Steam Deck. CPU reference in `include/flow_ref.hpp`, tested against known motion; GPU matches it bit for bit on the desktop. |
| 5 Interpolation | Done for now (flow guided interpolation, `VKIFRAME_INTERPOLATE=1`) with colour-guided vector weighting and a match-cost fade. Static-UI mask (`VKIFRAME_UI_MASK_THRESHOLD`) and the pan fallback (the whole frame cross-fades when most of the field cannot be matched) are in `flow_interp.comp`. |
| 5b Phase lock | `VKIFRAME_PHASE_LOCK` (default on) with `VKIFRAME_PHASE_OFFSET` (default 0.5): at a near-integer base/target ratio the content delay is slewed so the output ticks sit at fixed positions between native frames (t = 0.25 / 0.75 at 45 to 90). |
| 6 Integration | Mostly done: settings renamed `VKIFRAME_*` (old `FRAMEGEN_*` still read); implicit-layer manifest with `VKIFRAME_ENABLE`/`VKIFRAME_DISABLE`; `scripts/install.sh` and `uninstall.sh`; Decky plugin (panel, live settings, Benchmark button, copy buttons for launch options including the 32-bit one); `live.conf`, `live.log`, `status.json`, `stats.jsonl` and `bench.json` (private, 0600); measurement logic and benchmark (`VKIFRAME_STATS`, `scripts/vkiframes-bench.sh`); refresh-rate clamp and cost warning (unit-tested only, because the Deck reports `refresh_hz` 0); security checklist done. The layer loads in Steam games on the Deck (Cuphead, Cult of the Lamb, Tomb Raider 2013 with `PROTON_USE_WOW64=1`, since the layer is 64-bit). Open: hiding `VK_EXT_present_timing` from games, resize handling, the debug overlay. |

## Measurements

* **Flow cost, desktop RX 9070**: 1.09 ms per pair at 500x500.
* **Flow cost, Steam Deck at 1280x720**: half resolution field 7.5 to 9.2 ms per pair; quarter resolution field (default, `VKIFRAME_FLOW_LEVEL=2`) 7.2 ms; with the narrower middle level search and sub-pixel vectors **4.8 to 5.0 ms per pair** (about 22 percent of GPU time at 45 pairs per second). Whole Deck GPU reading in Cuphead 45 to 90: about 36 to 38 percent.
* **Interpolation quality**: on test frames (a rotating cube, predicting a real middle frame), the interpolation error is about 3 times lower than the cross-fade. A quarter resolution field was more accurate than the half resolution one, and the sub-pixel fit lowered the error further. On a synthetic sprite scene the colour guidance cut the error along the outline by only about 2 percent; the match-cost fade never triggered there (costs stay below 0.025).
* **Phase lock cost**: the content delay rises from about 22.3 ms to 29.5 ms (+7 ms) with the lock at offset 0. Offset 0.5 puts both ticks of a pair between native frames.
* **Cuphead on the Deck, 45 to 90, interpolation (user, same session, by feel)**:
  * lock off, guide and cost fade off: smoother, a lot more noticeable distortion;
  * lock off, guide and cost fade at defaults: smooth, noticeable distortion (less than above);
  * lock on at offset 0 (a native frame every pair): reduced edge distortion but choppy (sharp and soft frames alternate at 45 Hz);
  * **lock on at offset 0.5, defaults for guide and cost fade: smoothest; distortion noticeable only when there are lots of lines on screen; ghosting on character movement passable.** This is the best setting so far and the default now.
* **GPU cost per stage, Steam Deck, Cult of the Lamb, 45 to 90, flow level 2 (log lines `flow stages` and `interpolation: GPU`, user's Deck, 2026-10-30)**:
  * flow, per pair: 4.8 ms = pyramid 0.3, coarse 1.25, refine L3 1.45, refine L2 1.75, occlusion 0.02 (5.2 to 5.5 ms when the game is busy, one window 6.4);
  * interpolation, per synthetic frame: 2.35 ms with the pan check read per pixel (48 samples), **0.77 ms** with it computed once per workgroup (commit 03a8e62); the output is identical;
  * layer cost per 22 ms base frame (flow + two interpolations): about 9.5 ms before, about 6.3 ms after;
  * `VKIFRAME_FLOW_BWD_SKIP=2` (skip the finest backward refine at any level, mask from a 160x90 field): expected about 0.9 ms per pair at level 2, measured on the Deck: refine L2 1.75 -> 0.91 ms, flow 4.85 -> 4.02 ms per pair (Cuphead, 45 to 90). **Look test, Cuphead: the smudging on the trees is much more noticeable than without the skip (user, 2026-10-30), so it stays off by default**; Lamb showed no visible difference. Mode 1 (default) only acts at flow level 1.
* **Two-sided interpolation (`VKIFRAME_INTERP_BIDIR=1`, default on)**: A is moved forward along A -> B, B is moved back along B -> A, each trusted by its own match cost and occlusion mask, so uncovered background comes only from B and covered background only from A. Offline (`interp_eval`, method `bidirectional`): Cuphead dash, trackable triplet MAE 0.0258 against 0.0274 for the single interpolation (6% lower; 8% lower on hard pixels), with visibly cleaner tree-trunk edges; the single interpolation's block patches are still visible in both. It needs the full-resolution backward flow, so it turns `VKIFRAME_FLOW_BWD_SKIP` off. **Deck test (Cuphead, 45 to 90, 2026-10-30)**: compiles and runs; interpolation 1.15 ms per synthetic frame against 0.78 ms without (+0.37 ms), flow unchanged at 4.86 ms per pair (the full backward flow is already refined at level 2); the owner reports the frames are a lot smoother (the whole build) but the trees still interpolation, so it is **off by default**; kept as an optional switch.

* **Benchmark 1, Steam Deck, 30 to 90 (base-rate cap 30, `max_synthetic` 4, owner's run, 2026-10-31)**: frame time 33.40 ms off and 33.38 ms on, so the layer cost on the game is **-0.02 ms** (p95 -0.24 ms). The game was not GPU-bound at 30 fps, so the layer cost nothing visible. Layer GPU share 0.377 (flow 6.09 ms per pair, interpolation 2.18 ms per generated frame). Shown 89.7 fps; no cancelled, dropped or late frames. The 146 to 149 ms frame-time maxima occur with the layer off and on alike.
* **Benchmark 2, Steam Deck, Tomb Raider 2013 (GPU-bound, 18.6 fps native, cap 60 not reached, target 90, owner's run)**: frame time 53.75 ms off, 56.20 ms on: mean cost **+2.45 ms** (4.6 %), per segment +1.97, +2.14, +3.22 ms (the Auditor recomputed these from `stats.jsonl`). Split by mode (Auditor): interpolating seconds (105 s) +0.90 ms, bypass seconds (62 s) +5.28 ms, so the headline number is mostly the bypass seconds. Game-thread waits rise from 0.07 to 2.27 ms per frame (gpu lock about 1.0 ms, command fence about 1.2 ms); because the game is GPU-bound, its CPU thread runs ahead, so these waits are only partly visible in frame time. Layer GPU share 0.089; flow 3.41 ms per pair, interpolation 0.96 ms per pass. The interpolation pass draws every shown frame, including the held native frame (k + 1 passes per native frame). Shown 59.4 fps against the 90 target. At 18 fps a second holds about 18 frames, so per-second p95 and p99 are close to the maximum: use means and per-segment differences only.
* **Benchmarks 3 to 5, Steam Deck, Tomb Raider 2013, same scene, target 90, cap 60 (owner's runs, Auditor's reading of the three `bench.json` files; no `stats.jsonl`, so no split by mode)**: with 8 command buffers the layer cost was +0.76 ms (off 56.50, on 57.26 ms) and with 16 buffers +2.27 ms (55.54 and 57.81 ms); flow level 3 gave +1.06 ms (54.04 and 55.10 ms). `VKIFRAME_CMD_BUFFERS=16` cut the game-thread waits from 1.74 to 0.09 ms per frame, but frame time with the layer on did not fall, so those waits are not what costs frame time when the game is GPU-bound. Flow level 3 cut flow from 3.43 to 2.34 ms per pair (-32 %) and kept the layer in interpolation more of the time (shown 66.6 fps against 54 to 55); whether level 3 looks acceptable is not measured (needs the offline error tool and a look test). The "off" baseline itself moves between 53.7 and 56.5 ms from run to run (about 5 %), more than the layer effect, so one run cannot tell +0.8 ms from +2.3 ms. Over the four runs the layer cost is +0.76 to +2.45 ms (mean about 1.6 ms, about 3 % of a 55 ms frame).
* **Benchmarks 6 to 9, Steam Deck, old scene (before the saved-game scene; will be redone), same scene and save for all four (GPU-bound, about 38 fps native with the layer off, target 90, cap 60; owner's runs, 6-pair `bench.json` of PR #17)**: cost = frame time on minus off, mean of 6 pairs; `layer_cost_within_noise` was `false` in all four. Layer cost was 6.11 ms (SE 0.04) with 8 command buffers at flow level 2, 6.06 ms (SE 0.04) with 16 buffers, 5.30 ms (SE 0.03) at flow level 3, and 4.71 ms (SE 0.02) at flow level 3 with `VKIFRAME_INTERP_BIDIR=0`. The game went from 37.9 fps (26.4 ms) with the layer off to 30.8 fps (32.5 ms) on, for 90 shown. The cost is the layer's own GPU time: one flow pass (3.14 ms) plus about 2.93 interpolation passes per game frame at 0.91 ms is 5.8 ms, and the remaining 0.3 ms is unexplained, probably blits and barriers (not measured). Command buffers 8 against 16 made no difference (0.05 ms, inside the noise), so 8 stays. Flow level 3 saved 0.81 ms and bidirectional off a further 0.60 ms (1.40 ms, 23 % of the layer cost in total); whether level 3 and bidir off look acceptable is not measured. No dropped or cancelled frames, and k = 2 in every on-second. `MAX_SYNTHETIC` was 10 in the last run (bidir off), per the Builder's reading of its `bench.json` settings echo, which neither the Builder nor the Auditor can see any more (set by the owner as a test; the echo does not record the `EXPERIMENTAL` flag that 10 needs, so the effective value may have been capped at 4); the files of the other three runs are not available to the Builder or Auditor, so their value is not established and must be read from each `bench.json` echo or `stats` file. k stayed 2, so by the Builder's reading it did not matter. The "off" baseline moved after a game restart (26.4 to 28.0 ms), so costs hold within a run but absolute fps does not compare across a restart. Run file names and the Auditor's reading are on the board (#2).
* **Benchmark series on the saved-game scene, Steam Deck, `main` 568d786 (owner's runs, six runs, 6 off/on pairs each, baseline = layer defaults plus `INTERPOLATE=1`, `TARGET_FPS=90`, `BASE_FPS_CAP=60`; 55.6 to 56.0 fps native with the layer off, GPU-bound; `layer_cost_within_noise` false in all five cost runs)**: layer cost (mean of 6 pairs, standard error) was 5.136 ms (0.010) at the baseline, 5.080 ms (0.003) with `CMD_BUFFERS=16`, 4.694 ms (0.006) with `INTERP_BIDIR=0`, 4.142 ms (0.006) at `FLOW_LEVEL=3` (new game session) and 3.746 ms (0.010) at level 3 with bidir off. The baseline cost is about 29 % of the layer-off frame time (17.99 ms); level 3 with bidir off is about 21 % (of 17.85 ms). Flow fell from 3.12 to 2.15 ms per pair at level 3, and interpolation from 0.905 to 0.708 ms per generated frame with bidir off. No late, dropped or cancelled frames in the five cost runs; 90 fps shown throughout. 16 buffers saved 0.06 ms in the same session, too small to act on, so 8 stays. Level 3 and bidir off cost less; whether they look acceptable is **not measured** (needs the offline error tool and the owner's look test). Sessions 1 and 2 are different game sessions, so absolute fps does not compare across them. `refresh_hz` is 0: the layer skips present timing in a game that uses present id itself, so the refresh-rate clamp has no data source here (which extension the game enables is not checked). Per-run files and the Builder's and Auditor's readings are on the board (#2).
* **`VKIFRAME_SYNTH_MARGIN=0` (one run, `TARGET_FPS=60`, `BASE_FPS_CAP=30`, `PHASE_OFFSET=0`, no control)**: the run is valid (native 30.00, shown 60.00, no late, dropped or cancelled frames), but passes per game frame averaged 1.619, not about 1.0: between 1.00 and 2.00 in stretches, 37 of 343 on-seconds within 1.0 ± 0.1 and 90 seconds at 2.0. **Measured**: the pass count is not steady. **Cause found by reading the code and an offline replay, not confirmed on the Deck**: the native-frame test covers only the start of a pair (t < 0.02), not the end, so a tick just before B's time gets t near 1.0 and is a full pass; the lock's dead band lets jitter decide which side a tick falls on, so the count wanders around 1.5. In the Builder's offline replay (built on the repo's scheduler code; the replay itself is not in the repo), counting t >= 0.98 as native too gives 1.000 passes per game frame in 8 of 10 seeds at 0.13 ms jitter (1.005 and 1.009 in the other two). A fix is new code and the owner's decision. The default settings (margin 0.15, phase offset 0.5) are not affected. No saving against the default margin can be claimed yet.
* **Reading of the benchmarks so far**: the layer is free when the game has GPU headroom (benchmark 1). When the game is GPU-bound it costs its own GPU time: about 5.1 ms per game frame at the baseline on the saved-game scene, about 3.7 ms with flow level 3 and bidir off. The earlier 38 fps scene gave 6.11 ms (23 % of the layer-off frame time), and the 18 fps scene 1 to 2.5 ms (2 to 4 %), cause not established; both are old scenes and are not carried over. The waits on the game thread are not shown to cost frame time when the game is GPU-bound. An async queue does not add GPU capacity, so it can only overlap work where units are idle: the cost is not an achievable gain (`async_gain_upper_bound_ms` is an upper bound only), and the async queue stays last. Two older checks stay open: dropped frames at about 18 fps (a record-only request is written and the run has started, no result yet; the baseline `MAX_SYNTHETIC` 3 caps a pair at 4 ticks, so 18 fps at target 90 would drop structurally, and the run sets `MAX_SYNTHETIC=4`), and the `STATS=0` cost (by reading the code it is one relaxed atomic load per present; a cross-build comparison is confounded, so it will be measured as a live `STATS` 0/1 toggle in one process with an external frame-time log, not yet done).

## Findings that changed the design

* **Display delivery was verified at protocol level.** `WAYLAND_DEBUG` on KWin shows the layer committing about 1184 distinct frames in 10 s, 1180 reported presented, 0 discarded, flips 8.333 ms apart. A MangoHud overlay loaded above the layer shows only the game's own present rate and cannot be used to measure the layer's output.
* **vkcube is a poor judge of frame rate quality**; a real game with its own clock is the test.
* **The tick marker and bar** (`VKIFRAME_TICKMARK=1|2|3`) are diagnostics that draw into the output frames; keep them out of normal use.
* **Games must run below the target to be interpolated.** With Cuphead at 90 on a 90 Hz screen the layer stays in bypass, as designed; use `VKIFRAME_BASE_FPS_CAP=45`.
* **Fractional t on every tick causes the most visible distortion.** Without the lock, every shown frame is moved at an arbitrary t. Holding the ticks at a fixed offset removes the beat; offset 0 gave uneven sharpness (choppy), offset 0.5 is uniform.
* **The mock tests ignore `VKIFRAME_*` variables from the shell** (a build shell with `VKIFRAME_TARGET_FPS=120` broke `mock_pacer`).
* The layer logs a `settings:` line at start so a log shows which options were active.

* **UI mask, offline (`tools/interp_eval`, `UI_MODE=1`, `HUD=x0,y0,x1,y1`)**: the HUD error drops to the cross-fade level (Lamb 0.0049 to 0.0032), but pixels of slow, flat motion are also taken as static, so whole-frame MAE rises at 0.03 (Lamb 0.043 to 0.045, Cuphead 2 0.027 to 0.032). A plain 3x3 difference of means was worse. Hence opt-in. Film grain keeps the mean \|A-B\| of a static HUD near 0.03, so thresholds below that do nothing.

* **Extrapolation (`VKIFRAME_EXTRAPOLATE=1`, offline, one native interval ahead)**: steady motion improves a lot (Lamb MAE 0.092 to 0.062, Cuphead dash 0.066 to 0.037); pans fall back to repeating the newest frame; near-static scenes are slightly worse than repeating (Cuphead 0.0011 to 0.0037, flow noise; a dead zone for vectors under 0.4 to 1.2 px helps a little). Latency: content delay at 15 fps with interpolation was 68 ms (one native frame); extrapolation shows the new frame on the next output slot, so the added delay is under one output frame (about 11 ms at 90 Hz). Untested on the Deck. **Start / stop / reversal check (9 triplets of the Lamb and Cuphead captures, one interval ahead):** on the 4 starts and stops the whole-frame fallback makes the prediction equal to repeating the newest frame (change -2 % to +0 %, no overshoot, no gain); the 2 steady triplets with real motion gain 33 % and 44 %; the one weak case is a stop into an almost static scene (Cuphead, error 0.0011 to 0.0037, tiny in absolute terms). Deck result at 15, 30, 45 fps base, 90 Hz: locked 90.0 fps, no drops. The base fps cap used for these tests waited before the present (every frame shown late by interval minus render time); it now waits after it (`VKIFRAME_CAP_EARLY=1` restores the old way).

## Open items
0. **Tree trunks and thin line art still distort** (Cuphead forest, user look test, 2026-10-30). The offline error images show block-shaped patches of constant displacement at the field resolution (320x180, 4 px blocks, patches of about 16 to 24 px), and a bright error band at trunk edges; the two-sided interpolation reduces the band but not the blocks. Ideas not yet tried: refine the field per pixel at the finest level only near edges, edge-aware (guided) filtering of the flow before the interpolation, a smaller final patch size at level 1 with the cost reduced elsewhere, `VKIFRAME_FALLBACK=near` for pans. Revisit after the next stage.

1. Occlusion strips (uncovered background behind a moving sprite) are cross-faded, which leaves a ghost; a one-sided fill from the frame that actually shows the background would remove it.
2. Dense line art still distorts; try stronger cost-fade thresholds (`VKIFRAME_CONF_LO/HI`) on the Deck and compare.
3. Refresh divisor snapping on the Deck; the UI mask default (0.08) still needs a Deck look test.
4. Lock stays off for non-integer ratios; its behaviour around game hitches (re-lock takes a few seconds) can be tightened.
5. Mock tests do not exercise the flow engine yet (stub shaders).
6. Hiding `VK_EXT_present_timing` from games (Stage 6); the Deck reports `refresh_hz` 0.00, so the refresh-rate clamp has never run on hardware.
7. **Bypass and dropped frames at a low base rate (not diagnosed).** In benchmark 2 the gate was closed in 62 of 167 on-seconds and 357 frames were dropped (265 while interpolating, 92 in bypass). It is not known whether the gate closes in seconds where the game stutters, or whether bypass itself costs. A test with the gate forced open or closed for a whole segment would separate the two.
8. **Flow cost drifts upward.** Flow took 4.8 ms per pair earlier, 6.1 ms in benchmark 1 and 7.5 to 8.4 ms in the minutes after it (the finest refine pass 2.0 to 3.4 ms). The cause is unknown (scene, clocks or heat).
9. **Waits on the game thread** (lock and command fence): `VKIFRAME_CMD_BUFFERS` (4 to 32, live setting, default 8; merged) removes the fence wait but did not lower frame time with the layer on, so the default stays 8. A deeper ring may add latency (`late_mean_ms` in the stats records would show it). Recording outside the mutex is a separate change that is not planned.
